# Amazon Tracking-ID Implementation Plan — 18 August 2026

## Current state

- Current Store ID / main tracking ID: `apfunbox06-21`.
- Amazon also shows `onamzapfunbox-21` in the account selector, but this audit did not assign it to a page or category.
- Existing products store a complete `affiliateLink` URL in Sanity, mostly as `amzn.to` short links.
- The rendered CTA uses the stored URL unchanged. The application does not currently append or replace an Amazon tag.
- The `affiliateLink` document schema supports merchant URLs and status metadata, but it does not contain a tracking-ID field.
- Short links do not reveal their underlying tracking ID to the browser, so page analytics cannot reliably infer it.

Do not rewrite existing links globally. That could break SiteStripe attribution and would make rollback difficult.

## Least-complex future architecture

Use one optional tracking ID at the **top-ten list/page level**, with an optional per-product override only if a real operational need appears.

Recommended future Sanity fields:

```ts
// topTenList
amazonTrackingId?: string

// product or affiliateLink, optional override
amazonTrackingId?: string
```

Resolution order:

1. Explicit product/affiliate-link tracking ID.
2. Page/list tracking ID.
3. No value—preserve the URL as stored.

The field is measurement metadata, not permission to mutate the destination URL. Generate the category-specific link in Amazon SiteStripe first, save that complete link in `affiliateLink`, and store the matching ID beside it for reporting.

## Where the owner inserts future IDs

After creating IDs in Amazon Associates:

1. Open the relevant `topTenList` document in Sanity Studio.
2. Enter the exact Amazon-issued ID in the future **Amazon Tracking ID** field.
3. Replace each product's stored affiliate URL only with a link generated by Amazon for that ID.
4. Verify the destination and tag in Amazon Associates before publishing.

Possible future page mappings—only after the IDs actually exist—are:

| Page/category | Suggested purpose, not an ID |
|---|---|
| Electric shavers | Attribute shaver-list traffic |
| Beard trimmers | Attribute trimmer-list traffic |
| Air fryers | Attribute air-fryer-list traffic |
| Baby monitors | Attribute parenting-commerce traffic |
| Dash cams | Future experiment; not implemented in this task |

## Frontend support

The current click listener already sends `affiliate_tracking_id` when either:

- the link contains explicit `data-affiliate-tracking-id`, or
- a direct Amazon URL contains a `tag` query parameter.

To complete future support safely:

1. Add the optional field to the Studio schema.
2. Include it in the relevant GROQ projection.
3. Pass it to CTA components as `data-affiliate-tracking-id`.
4. Do not append it to shortened URLs client-side.
5. Test one category at a time in Amazon and GA4.

No category-specific tracking ID was invented, assigned or substituted in this implementation.
