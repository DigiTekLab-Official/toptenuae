### Dynamic Routing Logic — `[category]/[slug].astro`

The most complex route. It handles **5 content types** with a 2-step Sanity fetch + type dispatch:

```
1. Parallel fetch: all category slugs + docType for the slug
2. Dispatch:
   - docType == 'topTenList'  → TOP_TEN_LIST_QUERY
   - docType == 'howTo'       → HOW_TO_QUERY (inline GROQ)
   - else                     → GENERIC_POST_QUERY
3. Determine correct category from content data
4. Apply normalization map:
   travel-tourism → events-holidays
   health-fitness → lifestyle
   baby-kid       → parenting-kids
   buyers-guide   → reviews
5. If URL category != correct category → 301 redirect
```
Source: `src/pages/[category]/[slug].astro:16-96`

### Smart Redirects — `reviews/[slug].astro`

When the wrong content type hits `/reviews/[slug]`:
```
topTenList  → 301 /top-ten/{slug}
holiday/event/article → 301 /events-holidays/{slug}
howTo/tool  → 301 /{computed-category}/{slug}
```
Source: `src/pages/reviews/[slug].astro:22-30`

### Middleware Redirects — `src/middleware.ts`

Executes on every non-asset request before the route handler:

| Trigger | Action | Status |
|---------|--------|--------|
| `www.` prefix | Strip www | 301 |
| Uppercase in path | Lowercase | 301 |
| `fbclid`, `gclid`, `utm_source`, `utm_medium`, `utm_campaign`, `ref` params | Strip params | 301 |
| `.php`, `/cgi-bin/`, `webmail.`, `cpanel.` | 404 response | 404 |

Source: `src/middleware.ts:30-56`

## 4. Content Architecture

### Sanity Content Types

All schema definitions live in `/Users/ameer/Developer/00-Shared-Core/universal-studio/schemaTypes/topten/`

#### 1. `topTenList` — Ranked List Articles
- Purpose: "Best of" listicles (e.g., "Top 10 Laptops in UAE")
- Key fields: `listItems[]` (each with `product` ref, `rank`, `badgeLabel`, `whySelected`), `body` (Portable Text), `faqs[]`
- URL: `/top-ten/{slug}` OR `/{category}/{slug}` (via `[category]/[slug].astro` dispatch)
- Schema output: `ItemList` + `BreadcrumbList` + `FAQPage` (if faqs present)
- Source: `schemaTypes/topten/topTenList.ts`

#### 2. `product` — Product Reviews
- Purpose: Individual product reviews with affiliate links
- Key fields: `brand`, `reviewSection` (enum controls category), `price`, `currency`, `affiliateLink`, `pros[]`, `cons[]`, `specifications[]`, `customerRating`, `reviewCount`, `verdict`
- URL: `/reviews/{slug}`
- Schema output: `Product` + `AggregateRating` + `Review` + `Offer`
- Source: `schemaTypes/topten/product.ts`

#### 3. `category` — Navigation & Content Grouping
- Purpose: Defines navigable category sections
- Key fields: `menuLabel` (slug source), `title` (H1), `slug`, `metaTitle`, `description`, `intro` (Portable Text), `featuredPosts[]`, `parentCategory` (hierarchical), `isHidden`
- URL: `/{slug}`
- Schema output: `CollectionPage` + `BreadcrumbList`
- Source: `schemaTypes/topten/category.ts`

#### 4. `tool` — Calculator/Utility Tools
- Purpose: Free UAE finance calculators
- Key fields: `componentId` (maps to Astro calculator component), `intro`, `body`, `faqs[]`, `relatedTools[]`
- URL: `/{category}/{slug}` (typically `/finance-tools/{slug}`)
- Schema output: `SoftwareApplication` + `FAQPage`
- Source: `schemaTypes/topten/tool.ts`

#### 5. `deal` — Time-limited Offers
- Purpose: Deals and promotions with countdown timers
- Key fields: `product` (ref, auto-fills details), `dealPrice`, `originalPrice`, `discountPercent`, `dealStartDate`, `dealEndDate`, `couponCode`
- URL: `/deals` (all deals on one page; **no individual deal slug pages**)
- Schema output: `Offer`
- Source: `schemaTypes/topten/deal.ts`

#### 6. `howTo` — How-to Guides
- Purpose: Step-by-step instructional content
- Key fields: `howToSteps[]` (structured steps), `body`, `faqs[]`
- URL: `/how-to-guides/{slug}` (via `[category]/[slug].astro` dispatch)
- Schema output: `HowTo` + `FAQPage`
- Source: `schemaTypes/topten/howTo.ts`

#### 7. `holiday` — Events & Holidays
- Purpose: UAE events, public holidays, festivals
- Key fields: `startDate`, `endDate`, `locationName`, `address`, `ticketPrice`, `ticketUrl`, `status`
- URL: `/events-holidays/{slug}`
- Schema output: `Event` + `Offer` (if ticketed)
- Source: `schemaTypes/topten/holiday.ts`

#### 8. `author` — Author Profiles
- Purpose: Editorial attribution
- Key fields: `name`, `image`, `bio`
- No dedicated URL (author pages don't exist; `/author/` blocked in robots.txt)
- Source: `schemaTypes/topten/author.ts`

#### 9. `siteSettings` — Global Configuration
- Purpose: Nav menu, footer data, site-wide settings fetched via `SITE_SETTINGS_QUERY`
- Source: `schemaTypes/topten/siteSettings.ts`

#### 10. Other types: `institution`, `aviationEntity`
- Niche content types; inferred to serve category-specific sections
- Source: `schemaTypes/topten/institution.ts`, `aviationEntity.ts`

### Content Generation Flow

```
Editor creates/edits content in Sanity Studio
        ↓
Sanity publishes to production dataset (kxdjzy8e)
        ↓
Page request hits Cloudflare edge
        ↓
Astro SSR route fetches via Sanity client (useCdn: true, perspective: published)
        ↓
Content rendered server-side → HTML response
        ↓ (optional)
POST /api/revalidate triggers cache purge
```

The Sanity client uses CDN (`useCdn: true`) and only `published` perspective — draft content is never served.

## 5. SEO Architecture

### Canonical Tags

Set in `BaseLayout.astro:95`:
```html
<link rel="canonical" href={canonicalUrl} />
```

`canonicalUrl` resolution logic (`BaseLayout.astro:32`):
```js
const canonicalUrl = canonical || new URL(Astro.url.pathname, siteUrl).href;
```

- Pages **explicitly set** canonical: `[category]/[slug].astro:95`, `reviews/[slug].astro:38`, `top-ten/[slug].astro:23`
- Canonicals are hardcoded with the `https://toptenuae.com` base — no protocol ambiguity
- Category normalization in `[category]/[slug].astro` ensures canonical uses the **normalized** category slug

### Metadata Generation

All meta tags are in `BaseLayout.astro` (lines 86–158). Every page must pass:
- `title` → auto-suffixed: `if (!title.includes('TopTenUAE')) title += ' | TopTenUAE'` (`BaseLayout.astro:30`)
- `description`
- `canonical` (optional; defaults to current URL)
- `ogImage` (optional; defaults to `/images/brand/og-default.png`)

SEO title/description resolution per page type:
- `[category]/[slug].astro:93-94`: `data.seo?.metaTitle || data.title`, `data.seo?.metaDescription`
- `reviews/[slug].astro:39-40`: `data.seoTitle || viewData.title`, `data.seoDescription || data.itemDescription || data.verdict`
- `top-ten/[slug].astro:23-24`: `data.seoTitle || data.title`, `data.seoDescription`

### Dynamic URL Generation

**Slugs** come from Sanity's `slug.current` field on each document. The `[category]` segment is determined by:

1. The document's `category.slug.current` or `categories[0].slug.current`
2. Applied through the normalization map in `[category]/[slug].astro:29-36`:
   ```
   travel-tourism  → events-holidays
   health-fitness  → lifestyle
   baby-kid        → parenting-kids
   buyers-guide    → reviews
   ```
3. Content type defaults:
   ```
   holiday/event → events-holidays
   tool          → finance-tools
   howTo         → how-to-guides
   (default)     → reviews
   ```

**Title-to-slug:** Sanity generates slugs from the `title` field (configured on each schema type). No auto-generation in Astro — slugs are editorial.

### Duplicate URL Risks

| Risk | Description | Source |
|------|-------------|--------|
| **Dual-route overlap** | A `topTenList` document can be accessed at both `/{category}/{slug}` AND `/top-ten/{slug}`. Only `[category]/[slug].astro` will handle a request for a `topTenList` via a category path; it fetches with `TOP_TEN_LIST_QUERY` when docType == 'topTenList'. However, the canonical set by `[category]/[slug].astro:95` uses `masterCategory` (normalized), which may differ from `top-ten`. | `[category]/[slug].astro:86-96` |
| **Category normalization gaps** | Content with `reviewSection` (e.g., `tech`, `home-kitchen`) on `product` type may not have a matching category slug. If the normalization map doesn't cover the value, the page may redirect to `/404`. | `[slug].astro:29-36` |
| **No trailing slash enforcement** | `trailingSlash: 'never'` in config, but no active redirect for incoming trailing slash (middleware only handles www, uppercase, tracking params). Cloudflare Pages may handle this natively. | `astro.config.mjs:98` |
| **`/reviews` + `/[category]/[slug]` overlap** | The `[category]/index.astro` explicitly rejects `reviews` as a category (redirects to 404). But `/reviews` is served by `reviews/index.astro`. This is correct — just a potential confusion point if a category named `reviews` is created in Sanity. | `[category]/index.astro:13-16` |

## 8. Technical Risk Assessment

### Duplicate Content Risks

| Risk | Severity | Evidence |
|------|----------|---------|
| **TopTenList reachable via two URLs** | Medium | A `topTenList` at slug `best-laptops-uae` could be hit at `/top-ten/best-laptops-uae` AND `/{its-category}/best-laptops-uae` (if the category matches). The canonical in `[category]/[slug].astro` uses `masterCategory` from the data, which may not be `top-ten`. The canonical in `top-ten/[slug].astro` hardcodes `/top-ten/{slug}`. If both URLs resolve, they will have **different canonicals**. | `[category]/[slug].astro:95`, `top-ten/[slug].astro:23` |
| **Product title forced to end in "Review"** | Low | `reviews/[slug].astro:34` appends " Review" to title if not already present. This affects the `<title>` tag and OG title, but canonical and URL remain unchanged. | `reviews/[slug].astro:33-35` |
| **No pagination** | Low | Category listing pages show all items without pagination. Long lists may cause thin-per-item indexing concerns at scale, but no duplicate URL risk per se. | `[category]/index.astro` |

### Crawl Budget Risks

| Risk | Severity | Evidence |
|------|----------|---------|
| **SSR on every request** | Low-Medium | All content pages are SSR (not statically generated). Each crawler hit triggers a Sanity API call. Under heavy crawl, this could slow responses. `useCdn: true` mitigates via Sanity's CDN cache. | `src/sanity/lib/client.ts` |
| **`/deals` has no individual pages** | Positive | Deals are aggregated on one page. No crawl budget wasted on ephemeral deal URLs. | `deals/index.astro` |
| **Search page indexed** | Low | `/search` is not in the sitemap exclusion list and appears to be indexable (no `noIndex` prop confirmed). Search result pages are typically not valuable for Google. | `astro.config.mjs:21-27` |
| **`/[category]` catches ALL category slugs** | Medium | Any Sanity category slug becomes a live URL. If categories are renamed/deleted in Sanity without redirects, old URLs return 404. | `[category]/index.astro` |

### Canonical Risks

| Risk | Severity | Evidence |
|------|----------|---------|
| **TopTenList canonical mismatch** | High | As noted above: `top-ten/[slug].astro` sets canonical to `/top-ten/{slug}`. But `[category]/[slug].astro` sets canonical using `masterCategory` which could be `reviews` or `tech` if that's what the document's category field says. If Googlebot hits both, it sees **conflicting canonicals**. | Both slug pages |
| **Fallback canonical uses Astro.url.pathname** | Low | If `canonical` prop is not passed, `BaseLayout` falls back to `new URL(Astro.url.pathname, siteUrl).href`. For SSR this is the actual request URL — correct, but means URL normalization (www, uppercase) must work before the page renders. Middleware handles this. | `BaseLayout.astro:32` |
| **OG URL == canonical** | Good | `og:url` uses `canonicalUrl`, so OG URL always matches canonical. | `BaseLayout.astro:120` |

### Redirect Risks

| Risk | Severity | Evidence |
|------|----------|---------|
| **Redirect chains possible** | Medium | Middleware 301 (www/uppercase/tracking) → then page-level 301 (wrong category). If both trigger on one request, Cloudflare sees a two-hop chain. Middleware runs first per Astro's execution model, so this is sequential but double-redirecting. | `middleware.ts`, `[category]/[slug].astro:83` |
| **Broken normalization** | Low | If a category slug like `health-fitness` is used in a URL and the content has been moved to `lifestyle` in Sanity, the redirect fires. But if the content no longer exists at `lifestyle/{slug}` either, the user gets a 404 after the 301. | `[category]/[slug].astro:77-83` |

### Thin Content Risks

| Risk | Severity | Evidence |
|------|----------|---------|
| **Category listing pages** | Low-Medium | `/{category}` pages render all items in a grid. If a category has 1–3 items, the listing page is thin. No minimum item threshold enforced in code. | `[category]/index.astro:30` |
| **Deals page** | Medium | `/deals` is a single aggregated page. If deals are time-limited and expire, the live content shrinks. `dealEndDate` field exists but no auto-removal from page if expired. | `schemaTypes/topten/deal.ts` |
| **Tool pages** | Low | Tools have `intro`, `body` (Portable Text), `faqs[]`. If a tool is published with only the calculator and no editorial body, it may be thin. | `schemaTypes/topten/tool.ts` |

## 10. Project Knowledge Base

### How the site works

TopTenUAE is a UAE-focused affiliate + editorial content site built on Astro 6 with SSR via Cloudflare Workers. Content is entirely managed in Sanity CMS. There is no database — Sanity is the source of truth for all content. The site uses React 19 "islands" only where interactivity is required (navigation drawer, forms, calculators rendered client-side). All page shells and SEO metadata are rendered server-side.

### How content flows

1. Editors create/edit content in Sanity Studio (`universal-studio.sanity.studio`, at `/topten` project path).
2. Content is saved to the Sanity production dataset (`kxdjzy8e/production`).
3. A page request arrives → Cloudflare routes to the Astro SSR Worker.
4. The Astro page fetches data from Sanity via `@sanity/client` (`useCdn: true`, `perspective: published`).
5. The page is rendered server-side with all SEO metadata, JSON-LD, and HTML.
6. The response is returned to the client (optionally cached at Cloudflare edge).
7. React islands hydrate client-side for interactive elements.

### How pages are generated

- **Homepage** (`index.astro`): Fetches `HOME_QUERY` which returns hero post + category-grouped sections.
- **Category hubs** (`[category]/index.astro`): Fetches `CATEGORY_PAGE_QUERY` by slug; renders grid of items. Explicitly blocks `reviews` and `deals` from this route.
- **Content detail** (`[category]/[slug].astro`): Two-step parallel fetch (doc type + valid categories). Dispatches to the correct query based on type. Validates and normalizes category, redirecting if wrong URL. Sets canonical to the normalized category URL.
- **Product review** (`reviews/[slug].astro`): Fetches `PRODUCT_BY_SLUG_QUERY`. Smart-redirects wrong content types. Forces title to end in "Review".
- **Top-ten detail** (`top-ten/[slug].astro`): Fetches `TOP_TEN_LIST_QUERY`. Sets canonical to `/top-ten/{slug}`.
- **Deals** (`deals/index.astro`): Single aggregated feed from `ALL_ACTIVE_DEALS` query.

### How URLs are generated

- Slugs are **editorial** — set in Sanity CMS, generated from the `menuLabel` (categories) or `title` (content) field.
- Category segment is determined dynamically from the content document's category reference, with a normalization map applied.
- Trailing slashes are never added (`trailingSlash: 'never'`).
- `www.` is stripped and uppercase paths are lowercased by middleware (301 redirects).
- Tracking parameters (`utm_*`, `fbclid`, `gclid`, `ref`) are stripped by middleware (301 redirects).
